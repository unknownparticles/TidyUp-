# 收纳整理师 - 货柜消除 3D (Goods Sort Game)

参考经典货柜收纳与 3 消益智游戏制作的精美 Web 版游戏。

## 🌟 游戏核心机制

1. **3 消匹配消除**：
   - 将 **3 个完全相同的物品** 移动到同一个货柜格子或传送货架中即可完成配对消除。
   - 触发高分连击、星星粒子飞溅与清脆消除音效。

2. **空间与前后遮挡层级机制**：
   - 上方为主要操作柜（9 个大格，每格可容纳 3 个物品），下方为 3 行自动滚动的备选传送货架。
   - **前后深度遮挡**：前排物品被移走或消除后，后排被遮挡的物品（**低饱和度状态**）将立即激活移到前排并展现绚丽色彩，可被抓取。

3. **下方三行传送货架自动滚动**：
   - 下方 3 行迷你货架呈交替方向横向自动滚动。
   - 带有留白空格，玩家可利用空格进行灵活的中转周转。

4. **四大辅助道具**：
   - 🔨 **锤子 (19)**：强制消除任意指定的单个物品，解除卡手障碍。
   - 🪄 **魔棒 (41)**：自动在全场中寻找并配对消除一组 3 消物品。
   - ❄️ **冰冻 (67)**：暂停倒计时与减速，获得宝贵思考时间。
   - 🔄 **重排 (+)**：打乱并重新排列当前可见的物品位置，化解死局。

5. **音效与视觉**：
   - 基于 Web Audio API 自研纯原生合成音效（点击、拾取、放置、消除和弦、锤击碎裂、魔棒魔法、冰冻寒芒、通关号角）。
   - Canvas 物理粒子引擎，支持星星爆破与彩带飞舞。

## ⚙️ GitHub Pages 部署说明

游戏运行采用原生前端技术（HTML5 + CSS3 + 原生 JavaScript + Web Audio API + Canvas），运行时无需第三方库。发布时用 esbuild 压缩脚本和样式，只打包实际使用的资源到 `dist/`，支持各类静态托管：

1. **GitHub Actions 自动部署（已配置）**：
   - 仓库内已包含 `.github/workflows/deploy.yml`。
   - 提交代码到 `main` 分支将自动安装构建依赖、运行测试并生成 `dist/` 后部署。
   - 在 GitHub 仓库设置 `Settings -> Pages -> Build and deployment -> Source` 选择 **GitHub Actions** 即可。

2. **分支根目录直接托管（备选方案）**：
   - 也可在 `Settings -> Pages -> Build and deployment -> Source` 选择 **Deploy from a branch**。
   - 分支选择 `main`，目录选择 `/ (root)`，保存后即生效。

## 🏷️ 版本规范与自动递增

游戏在点击右下角 **暂停** 按钮时，弹窗顶部会清晰展示当前游戏版本号（例如 `版本号：v1.1.0`）。

### 版本号自增规范
- 🚀 **大功能**：大版本号 +1（Major +1，例如 `1.1.0` -> `2.0.0`），执行：
  ```bash
  npm run bump:major
  ```
- ✨ **小功能**：小版本号 +1（Minor +1，例如 `1.0.0` -> `1.1.0`），执行：
  ```bash
  npm run bump:minor
  ```
- 🐞 **修复优化**：补丁号 +1（Patch +1，例如 `1.1.0` -> `1.1.1`），执行：
  ```bash
  npm run bump:patch
  ```

## 🎨 物品照片与木色货架

当前物品库共 165 张物品照片，包含原「新物品单品」目录中的 150 张在用照片及补充的 784–798 号手提包、游戏机、饼干和汽水罐，保留原图造型、材质和颜色。素材位于 `assets/items/photos/`，物品编号与原始文件名对应。页面直接使用项目内素材，运行时不依赖下载目录。

- **透明背景**：仅去除与图片外边缘连通的近白背景，保留主体内部的白色衣料、眼睛与标签。
- **图片压缩**：全部在用照片采用 WebP（质量 82），保留 `200 × 280` 尺寸与无损透明通道。导入脚本先并行压缩并验证完整批次；默认替换物品库，使用 `--append` 则追加或更新本批次物品。可运行 `npm run compress:items` 重新压缩。
- **统一尺寸**：照片保存为 `200 × 280` 透明画布，目录记录每张图片主体的实际边界。显示时按主体边界等比适配更高的物品位置，忽略透明留白，主体水平居中并底部对齐。柜格、滚动货架与拖拽预览共用尺寸和适配规则；宽屏取消原先的行高与物品宽度上限，浮板行高贴合物品和木板厚度。
- **物品目录**：`assets/items/items_data.json`、`src/items.js` 与独立运行的 `app.js` 同步使用完整照片物品库。关卡按物品类别选择，保留前后层、三消与拖拽机制。
- **木纹柜格**：`assets/ui/cabinet_wood.webp` 使用参考图无遮挡的木纹柜格行组成完整九宫格，去除原图顶部头像和计时栏。
- **界面配色**：参考图中的橘猫头像、深蓝紫顶栏、金黄色工具按钮与实木底栏用于统一界面。`assets/ui/cat_avatar.webp` 与 `assets/ui/toolbar_wood.webp` 从参考图裁切，游戏区域保留白色背景。弹窗按钮同步使用木色。
- **前后层显示**：不显示层数标签。后层保留色相与亮度，近后层饱和度降至 25%，深后层降至 15% 以表达深度，移到前层后恢复正常色彩。
- **紧凑排列**：柜格与底部浮板内的物品居中紧排，取消均分空隙，相邻物品轻微靠拢；物品与拖拽预览维持统一尺寸。
- **底部浮板**：`assets/ui/shelf_wood.png` 使用提供的木色浮板，按原图比例显示厚度，宽度随三个物品位置计算，仅留两侧 2 像素木边；物品站在浮板上缘，三行继续交替横向滚动。
- **离线资源**：首次先缓存小体积页面资源，当前关卡物品自动缓存。加载结束 15 秒后，浏览器空闲时以两路低优先级请求补齐照片库，完成后可离线进入任意关卡；下载中断时，已缓存的物品仍可使用，下次在线访问会继续补齐。节流模式或 2G 网络只缓存玩过的关卡。
- **缓存复用**：物品 URL 使用图片内容指纹，界面补丁更新不会重新下载未变化的图片。命中缓存后直接读取，并发请求共用一次下载，后层图片异步解码并延迟加载。
- **发布与读取**：`npm run build` 生成压缩的发布版，只包含页面需要的资源，不发布历史素材、脚本或测试。内置服务器支持 Brotli/Gzip、ETag 条件读取、版本化长效缓存和容量限制为 8 MiB 的内存缓存，重复请求无需重复读入和压缩文件。

重新导入照片需要 Python 3 与 Pillow：

```bash
python3 -m pip install -r scripts/requirements-assets.txt
npm run import:items -- /照片目录
npm run bump:minor
```

补充照片并保留现有物品库：

```bash
npm run import:items -- /补充照片目录 --append
npm run bump:minor
```

`assets/` 仅保留当前物品、界面与安装图标资源，历史几何物品、旧背景及对应生成脚本已移除。导入时自动排除已删除的 801、805、829、833、835、842、849、857、859、893、906、912、913、935、937、938、954、963、965、966、968、990 和 995。

> 💡 **Git Hook 自动化**：已配置 `.githooks/pre-commit`。每次提交代码时，若未手动修改版本号，提交钩子将自动按小功能规则递增小版本号并同步更新 `package.json`、`app.js` 与 `index.html`。若为大功能提交，可提前运行 `npm run bump:major` 或使用 `BUMP=major git commit -m "..."`。
